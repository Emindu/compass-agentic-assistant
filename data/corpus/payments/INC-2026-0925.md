# INC-2026-0925: Month-end transfer slowdown after statement feature release

> MOCK DATA — fictional incident created for the Compass assessment POC.

## Summary

On 25 September 2026 (salary day), fund transfers took up to 3 minutes and 7% timed out. The
problem started one day after release 4.18, which added running balances to mini statements.

## Impact

- Duration: 2 h 05 min (09:30–11:35)
- About 31,000 transfers timed out; customers retried, which added load

## Timeline

- 09:30 Latency alarm on payments-ledger
- 09:50 PgBouncer shows all server connections busy; clients queued
- 10:30 Profiling finds the new mini-statement endpoint runs one query per transaction line
- 11:10 Feature flag turns running balances off
- 11:35 Recovered

## Root cause

Database connections ran out again. Release 4.18 introduced an N+1 query pattern in the
mini-statement endpoint; each request held a connection for 40–60 queries. At salary-day
traffic, connection demand exceeded what PgBouncer and the database allowed, and transfer
postings waited for connections. Load testing for 4.18 used normal-day traffic only.

## Resolution

Feature flagged off; query rewritten as a single windowed query and re-released on 29 September.

## Action items

- PAY-2580: Salary-day load profile mandatory in release performance tests
- PAY-2581: Separate connection pools for read-heavy statement traffic and postings
