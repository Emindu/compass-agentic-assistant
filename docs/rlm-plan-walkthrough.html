What the generated Python does, and which data it touches

The code model writes a short Python plan. The plan never sees data directly: it runs in an empty child process and can only call four functions. Each call goes back to the parent API process, which reads the data and applies the user's clearance from their token.

What the plan cannot do, and which layer stops it

    

      
import os · open("…")
AST check before the run: imports allowed only from json, re, math, statistics, collections, itertools, datetime, functools. No open, eval, exec or getattr. Checked again at run time.

      
x.__class__.__bases__
AST check: no names that start with __, no attributes that start with _. Builtins are an allow-list.

      
list_documents(access_level="restricted")
Unknown arguments are rejected. Clearance comes from the session, never from the plan.

      
get_sections("POL-SEC-004")
Hidden and missing documents both return [], so the plan cannot learn that a hidden one exists.

      
while True: search(…)
40 calls, 30 s wall clock, CPU and memory limits. The child is killed when the run ends.

      
os.environ["MISTRAL_API_KEY"]
The child starts with an empty environment and no network, so it has no key and nowhere to send one.
